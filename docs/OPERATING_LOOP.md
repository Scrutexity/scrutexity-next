## Components

| Component | Role | Location |
|-----------|------|----------|
| **AuditGPT** | Diagnostic engine — Free Snapshot + $497 Audit | `auditgpt.ai`, `~/Projects/auditgpt.nosync` |
| **Scrutexity** | Activation layer — Sprint, Monitoring, Partner OS | `scrutexity.com`, `Website/scrutexity-next/` |
| **Contento** | Fulfillment engine — rewrites, proof, AI snippets | `GEM/04-CONTENTO/`, `GEM/11-FULFILLMENT/` |
| **Obsidian** | Learning vault — sales logs, objections, patterns | `Scrutexity Proof Vault/` |
| **GEM** | Routing doctrine — playbooks, prompts, safety | `Gem/` directory |
| **Dataset** | Compounding asset — claim → evidence → outcome → pattern | `GEM/08-DATASET/` |

## Handoff Sequence

1. **AuditGPT** captures a prospect URL → produces claim inventory + proof gaps
2. **Scrutexity** reviews report → proposes Sprint or Monitoring
3. **Contento** fulfills Sprint → safer rewrites, proof page outlines, AI snippets
4. **Dataset** logs every claim as a structured row
5. **Obsidian** captures sales outcomes, objections, operator reactions
6. **GEM** ingests Obsidian patterns → updates playbooks, prompts, safety rules
7. **The loop repeats** — each iteration enriches the dataset and sharpens the system

## Doctrine

- No component publishes directly to the public — every output is a human-reviewable draft
- The dataset is the company — the audit product is how you acquire data
- Repeated patterns in Obsidian get promoted to GEM playbooks
- The loop compounds: more reports → richer dataset → sharper playbooks → better outreach → more reports
